# Coding Agent 应用与执行契约

应用首页为 `http://127.0.0.1:8483/#tasks`。任务、审查、项目配置、接入、企业、成员、权限、同步与审计共用导航、OIDC 会话和企业上下文。`/tasks` 入口也打开统一工作台。

交互原型位于 `/prototype.html`，明确显示“交互原型”，只使用浏览器本地数据，提供角色切换和外部事件演练。其页面、组件和样式与真实应用相同。在前端仓库执行 `npm run export:prototype` 可导出包含全部资源的独立 HTML；原型事件不作为真实执行证据。

## 创建与执行

项目管理员配置基准分支、已部署模型、允许修改范围、必过命令及每轮上限，保存后重新检查仓库与模型接入。此检查不宣称测试已经通过。新任务填写问题、复现、验收条件和多名指定审查者，可以选择代码起点，不要求已有 MR。创建使用幂等键；同一键的不同内容返回冲突。

每轮保存配置快照，包括模型、范围、检查和执行上限。新配置不改变正在执行的轮次。执行器领取任务后按实际项目路径检出准确 commit，读取仓库规则、运行基线检查、调用内网模型进行局部编辑，再运行配置的检查与原仓库提交 hook。产生有效修改后推送独立工作分支并创建 Draft MR，无修改不创建空 MR。推送以远端旧 head 为条件，人工新提交会使自动推送失败。

执行器代码未硬编码 storagepath 文件或验证命令。Helm 每个执行器按 `gitlabProjectID` 限定项目；各项目需要具备对应凭据和语言工具的执行器。修改范围过大时先选择最多 12 个相关文件，超出上下文容量则保留失败记录，由人缩小范围。默认每轮最多 3 次修复、30 分钟执行。

自动检查结果、独立模型判断与人工认可分别记录。模型可判断 `Met`、`Unmet` 或 `NeedsHuman`；检查通过不能替代人工认可，人工认可也不会合入 MR。任务完成以 GitLab 合入事实为准。

## 人工控制与反馈

人工介入立即递增 epoch 并关闭执行 gate。执行器终止子进程组，在退出后确认停止。停止未确认期间禁止恢复。授权或租约失效也关闭旧执行；重新授权不会恢复旧轮次。负责人、有效写权限和指定审查者资格分别校验，平台运营身份不隐含代码授权。

转交仅改变整个任务的负责人，不改变执行控制权、分支、MR 或正在执行的轮次。新负责人须有项目写权限。人工提交后，旧检查、判断和认可失效；负责人或项目管理员须明确确认新 head 后才能恢复。

GitLab 行级评论保留文件、行号、commit 和讨论上下文。同步不触发自动修改；指定审查者先整合冲突意见，再提交正式要求。执行中或人工处理期间的要求入队，人工处理不会因此恢复。代码变化后，旧版本要求须重新核对。同一任务至多一个活动轮次。

取消后迟到合入只更新 MR 事实，保留取消结果。关闭 MR 结束交付；重开不自动恢复。负责人明确继续后仍保持人工控制。

## 接口

| 方法与路径 | 行为 |
| --- | --- |
| GET `/api/v1/coding/connections` | 实际 GitLab、模型探测与当前会话身份接入状态 |
| GET / PUT `/api/v1/tenants/{tid}/projects/{pid}/coding-settings` | 查看 / 版本控制更新项目配置 |
| POST 同上 `/check` | 检查真实分支与模型存在，记录通过版本 |
| GET / POST `/api/v1/tenants/{tid}/projects/{pid}/tasks` | 查询任务 / 关联已有 MR |
| POST 同上 `/new` | 从新问题创建任务和第一轮配置快照 |
| GET 同上 `/{task}` | 任务、权限、轮次、验证、反馈与事件 |
| POST 同上 `/{task}/sync` | 同步 GitLab 当前代码、MR 与分页讨论 |
| POST 同上 `/{task}/actions` | 介入、恢复、转交、取消、继续、认可、正式反馈与队列核对 |

执行器使用服务身份访问 `POST /internal/v1/tasks/claim`、`POST /internal/v1/tasks/{task}/gate`、`POST /internal/v1/tasks/{task}/finish`。领取可按 project ID 限定，并报告执行器在线时间。gate 验证 epoch、worker、租约和当前代码写权限。

## 验证与实际边界

后端运行 `TEST_DATABASE_URL=... GIN_MODE=release go test -tags=nomsgpack -race -count=1 ./...` 与 `go vet -tags=nomsgpack ./...`；数据库测试使用隔离 schema。执行器边界测试：`python3 -m unittest discover -s scripts/task-executor -p 'test_*.py'`。

前端仓库运行 `npm run build`、`npm run test:prototype`、`npm run test:e2e` 和 `npm run test:tasks-smoke`。后两者需要私有联调配置；任务 smoke 使用协议测试客户端验证停止确认，不运行模型。`npm run test:whole-app` 才会运行真实模型、修改试点项目并创建 Draft MR，本轮迁移未执行该项。

原型涵盖澄清与同轮重入、停止超时、冲突和迟到事件。真实执行器尚未实现澄清暂停重入、主动停止通知、未提交修改回传下载和失败后带修改 Draft MR 的自动交付；外部 MR 更新仍需显式同步。当前单项目执行器不构成面向不可信仓库的完整租户隔离。已有执行输出中的补丁可以在 Vue 页面查看和下载。

API 和执行器均配置 `MODEL_URL`，模型名称从项目执行配置读取，执行时以轮次快照为准。仓库基准分支与模型存在性检查不会运行仓库测试。迁移验证记录见 [verification.md](verification.md)。
